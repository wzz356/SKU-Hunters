# 演示动线 — AI 新品企划工作室（小风扇场景深度演示）

> 导师口径：梳理底层业务逻辑链，聚焦 1-2 个典型场景**深度演示**，忌只秀 AI 功能。
> 本文档是答辩/演示的统一剧本：演示者说什么、评委看到什么、对应名创哪条业务规则。

## 一句话业务逻辑链

**商品经理下约束 → AI 在约束内做有依据的创意 → 五看洞察收敛机会 → 企划卡（创意+视觉+价格+节奏）→ 选样会改稿迭代 → 归档复盘**——把爆款从灵光一现变成数据可推演的确定选择。

## 演示主线：2027 夏季户外生活系列 × 小风扇

入口：前端 `http://localhost:5173`（后端 `:8000`，启动见文末检查清单）。

### 第 0 幕 · 任务中心（30 秒）
- **演示者说**："商品经理每年收到品类规划，要把'夏季户外'翻译成具体企划案。这里是任务入口。"
- **评委看到**：任务列表（含已归档的历史企划，可回看——归档不是封存）。

### 第 1 幕 · 企划约束（1 分钟）
- **操作**：展示约束卡（主题/品类/人群/价格带 39-99 元/成本上限 25 元/IP 策略三丽鸥/上新窗口）。
- **演示者说**："AI 不是自由发挥——约束由人下达，AI 在约束内做创意。成本上限 25 元是后面商品策略校验的红线输入。"
- **业务对应**：名创「年度品类规划 → 企划案」的约束下达（导师确认的真实流程）。

### 第 2 幕 · 洞察驾驶舱（3 分钟，**重点**）
- **操作**：三个模块逐个跑过程日志 → 内容淡入。
- **演示者说**（每个模块一条因果链，不讲功能讲逻辑）：
  - 趋势雷达："加载预采集社媒样本 → 聚类 → 识别 4 条上升期趋势，每条都标了跨品类关联领域——这是'五看'里的看趋势。"
  - 用户声音："823 条样本聚出 TOP4 痛点——第一名'太丑不想摆桌上'217 条，这是'看用户'。"
  - 竞品地图："价格 × 设计感矩阵定位出机会空白：50 元以内 × 高颜值 × IP 化无人占据——这是'看竞品'。"
  - 下方两块策展数据：名创内部爆品资产 + 流行元素板（色彩/纹样/形态可点击溯源到来源品类）。
- **评委看到**：每条结论都能点回样本与依据；页面顶部有数据来源说明条（预采集冻结演示数据）。
- **业务对应**：五看三定的"五看"；跨品类流行元素提取（导师专项要求）。

### 第 3 幕 · 机会生成（2 分钟）
- **操作**：思考过程日志逐行跑完（四维打分 → 初筛 10 个淘汰 7 个 → 保留 3 个）→ 3 张方向卡淡入。
- **演示者说**："机会不是生成的，是收敛出来的。每个方向挂四方依据链，可点击回溯——比如库洛米方向，依据是情绪趋势 + 痛点①④ + 竞品空白 + 名创已验证的库洛米联名模型。"
- **操作**：选定「IP 收藏风」方向。
- **业务对应**：打破单变量判断，多维交叉（导师确认的五看三定原则）。

### 第 4 幕 · 新品企划卡（4 分钟，**核心**）
- **操作**：企划生成思考过程逐行跑（创意锁定 → 即梦文生图 prompt → 跨品类融合 → 定价推导 → 节奏倒排 → **成本校验实时计算**）→ 企划卡淡入。
- **评委看到**：
  - 产品概念图（即梦文生图，三张方向各有冻结图）——企划案必须含视觉图稿（导师刚需）；
  - 跨品类融合说明：服装「薰衣草紫」× 潮玩「模块化组件」→ 盲盒收集逻辑移植小家电；
  - 定价 59 元 + 定价理由；上新节奏时间线（对齐 2027.05 夏季前窗口）；上市验证指标（动销率/连带率/UGC）；
  - 成本校验条：毛利率 58% ≥ 红线 30%，✅ 通过——**这个数字是管线实时算的，不是写死的**。
- **演示者说**："如果商品经理把成本上限改成 55 元，这张卡会被打回创意环节——校验规则写死在管线里，LLM 不能自由发挥。"

### 第 5 幕 · 改稿沟通（2 分钟）
- **操作**：点快捷建议「价格压到 55 元以内」→ AI 企划助手回复调整方案。
- **演示者说**："这对应名创选样会的来回迭代——企划案在选样和企划生成之间反复修改，不过就终止。"
- **业务对应**：选样会评审回环（导师确认的核心节点）。

### 第 6 幕 · 归档（30 秒）
- **操作**：归档 → 回任务中心 → 重新进入可回看全案 + 继续复盘追问。
- **演示者说**："归档不是封存。上市后动销数据回来，按周复盘——这接的是学习官回测飞轮。"

### 副线 · 趋势价值打分（如评委追问"趋势怎么判断有价值"，1-2 分钟）

演示当天提前（或现场）跑：

```bash
cd backend && ./venv/Scripts/python scripts/trend_scan.py
```

真实数据 → 四维打分 → 趋势卡：微博/百度/抖音/小红书/TikTok 五源热搜 +
淘宝联想词实时拉取，
每个候选趋势按**动能 35% / 契合 25% / 转化 25% / 窗口 15%** 加权打分，
分级为机会池（≥70）/ 观察（50-70）/ 淘汰——这就是机会生成环节"淘汰 7 个
保留 3 个"的真算法背书。快照写入 `backend/data/trend_scan_snapshot.json`，
也可通过 `GET /api/v1/trend-scan` 查看。

口径要点：**每个分数都挂依据链**（"动能 39 分 ← 当日热搜未命中 + 预采集增速 +78%"），
AI 只做表达不做"知道"——这是幻觉防线的核心叙事。模型偏保守是刻意的：
没有声量交叉验证的趋势进不了机会池，这本身就是决策纪律的体现。

### 副线 · 趋势历史回溯（如评委追问"增速是编的吗 / 来不及攒数据吧"，1-2 分钟）

演示当天提前（或现场）跑：

```bash
cd backend && ./venv/Scripts/python scripts/trend_backfill.py
```

UApiPro 热榜 API（免费聚合层，抖音/小红书/微博/什么值得买等 40+ 平台）
的**关键词历史检索**一次性搜出候选词过去 7 天全部上榜记录，按日分桶成
时间序列，前 3 天 vs 后 3 天求环比——增速从 fixtures 冻结数字升级为
**实测数字**，结果写入 `backend/data/trend_history.json`。

2026-08-14 实测结论（本身就是答辩素材）：
- **什么值得买（消费品类榜）**：风扇 7 天命中 4 天、香薰/露营均有命中，
  环比可算——消费趋势要看消费榜；
- **抖音/小红书/微博全民热榜**：细分品类词诚实零命中——全民榜以娱乐新闻
  为主，承载不了消费意图，这正是打分器要接淘宝联想词补转化信号的原因；
- 这个"哪个源对哪类问题有效"的实证结论，比任何一份 PPT 都能证明
  团队真的摸过数据。

### 副线 · 真实数据抽样（如评委追问"数据是真的吗"，1-2 分钟）

演示当天提前（或现场）跑：

```bash
cd backend && ./venv/Scripts/python scripts/refresh_real_sample.py
```

实时拉取四个公开数据源并写入 `backend/data/real_sample_snapshot.json`：

- **微博/百度热搜** × 演示关键词（风扇/露营/库洛米…）→ 社媒与大众搜索趋势信号
- **淘宝联想词** × 品类词 → 真实消费需求信号（历史抽样：「小风扇静音学生」「露营风扇超长续航」直接印证冻结样本里的痛点）
- **B站分区榜** × 品类词 → Z 世代 UGC 曝光信号

口径要点：**零命中 ≠ 故障**。热搜榜当日没有相关词条是正常结果（快照里 `scanned_sources` 证明确实扫过）；某源被风控（如 B站 code=-352）会记入 `failed_sources`/`failed_partitions`，其余源照常产出。打开快照 JSON 给评委看原始数据即可。

### 副线 · 飞书群机器人（如评委问到飞书工具，2 分钟）
- 群里 @机器人 发起圆桌评审会 → 五幕事件流实时推送到群 → 门节点卡片按钮（确认/打回/追问）→ 归档报告。
- 卖点：**进程重启后按钮决策仍可从 checkpoint 恢复**（注册表落盘 + sqlite checkpoint，已测）。

## 评委追问应答口径（统一答案）

| 追问 | 应答 |
|---|---|
| 数据是真的吗？ | 数据策略「真管线、冻数据」：样本预采集 + LLM 离线分析固化；管线、校验规则、决策逻辑是真实路径。live 模式接真实连接器（趋势官已接 Google Trends），失败自动降级回冻结数据。页面有数据来源说明条，不冒充实时抓取。**可现场跑真实抽样**（见下「真实数据抽样」环节）：微博/百度热搜、淘宝联想词、B站分区榜实时拉取，与冻结样本对照。 |
| 趋势价值怎么判断？ | 显式四维模型：动能 35%（热搜交叉命中+增速）、契合 25%（品类词库+价格带）、转化 25%（电商联想词购买意图占比）、窗口 15%（生命周期×开品周期倒排）。**不是 LLM 拍脑袋**——打分规则确定性可复现、可回测，每个分数挂依据链。现场可跑 `scripts/trend_scan.py` 验证；追问增速来源再跑 `scripts/trend_backfill.py` 展示 UApiPro 历史检索实测环比。 |
| 万级 SKU 分析呢？ | 我们的定位是把"万级 SKU"转化为可推演的方向管理：竞品地图按价格带分布（0-50 元占 42%）就是在售 SKU 大盘的固化切面；正式环境接内部 SAP 数据后可全量跑（导师确认内部数据暂不对飞书开放）。 |
| 112 国场景？ | 企划约束的市场字段 + GTM 官分国别计划（圆桌链路）；演示聚焦中国主场深度打磨（导师建议：1-2 个场景深度 > 全面铺开）。 |
| 图是 AI 画的吗？ | 即梦（火山引擎）文生图：设计语言 + 关键词组装 prompt 出图；演示环境用冻结出图，AK/SK 配置后 live 模式实时生成，失败自动回退冻结图。 |
| 为什么不是全自动？ | 名创的真实流程就是"人下约束、人选方向、选样会评审"——AI 做有依据的创意和校验，关键决策留给人。 |
| 学习官怎么学习？ | 飞轮已闭环：每场会议建档（方案/预测分/AI 建议/人决策/复盘轮数，bad case 同等入档），**下一场会议启动时台账自动反哺**——商业官的"历史相似案例"维度拿到真实过往记录（人决策是最有分量的信号），创意官把被否方案当负例避免换皮重提。实机验证：194 场历史档案已在真实会议 prompt 里流动。 |
| 用户洞察哪来的？ | 真用户官已接真实数据源：淘宝联想词（消费需求信号）+ 微博/百度热搜（社媒信号）并行拉取，LLM 归纳痛点与动机，**痛点频次由代码按热度归一计算**、证据链接代码从连接器返回构建——LLM 只写判断性文本，编不了数字和 URL。默认演示走 Mock（冻结数据永不翻车），`.env` 设 `AGENT_PROVIDER=real` + 配好 `LLM_API_KEY` 即六官全真（user/ip/business/gtm + trend/creative），LLM 或数据源故障自动回退 Mock。 |
| 成本/总分怎么算的？ | 真商业官：LLM 按锚点 rubric 出五维分数（0-100）+ 每条依据强制引用材料原句；**总分是代码加权算术**（Σ 分数×权重，schema 校验器强制容差 0.5，LLM 的 total 直接丢弃），置信度取上游最低（衰减不放大）。可逐笔复算。 |
| 多维表格/妙搭用了吗？ | 多维表格已真实集成：归档企划案时自动写一行到「SKU 企划归档库」（首次归档自动建表，字段含定价/成本校验/选中机会/设计语言）。演示时归档后页面出现"已同步飞书多维表格 ↗"标签，点开就是真实表格。妙搭未做——我们的前端是定制 React 页面，承载比妙搭表单更复杂的交互，这是取舍不是遗漏。 |
